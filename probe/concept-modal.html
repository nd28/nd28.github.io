01

The Entrance

A concept card opens

Every concept is a modal. The page behind it keeps running.

A learner taps a concept card. The app finds the concept, renders its title, body, and diagram into one modal, and opens it. Nothing else on the page stops — the app stays alive behind the sheet.

The sheet is a bottom sheet on phones: it slides up from the bottom edge and covers most of the screen. On a wide screen it becomes a centered card. Either way it is the same element — #conceptModal.

The modal is not a popup window. It is one element in the page, styled to float on top. Two things make it float: the modal itself (z-index 210) and a shared overlay behind it (z-index 200).

How a concept opensapp.jsrender first, open second
function openConcept(id) {
  const concept = CONCEPTS.find(c => c.id === id);
  if (!concept) return;
  currentConceptId = id;
  const data = getData();
  data.lastReviewed[id] = new Date().toISOString();
  data.lastConceptOpened = id;
  saveData(data);
  const isBookmarked = data.bookmarks.includes(id);

  document.getElementById('conceptBody').innerHTML = `
    <div style="display:flex;align-items:flex-start;justify-content:space-between;gap:0.75rem;margin-bottom:0.75rem;">
      <h3 class="concept-title" style="margin-bottom:0;">${concept.title}</h3>
      <button class="bookmark-btn ${isBookmarked ? 'active' : ''}"
        onclick="toggleBookmark(${id})" aria-label="Bookmark">${isBookmarked ? '★' : '☆'}</button>
    </div>
    <p class="cozy-text">${concept.body}</p>
    <div class="diagram-box">${concept.diagram}</div>
  `;
  document.getElementById('conceptFooter').innerHTML = `
    <button class="btn btn-primary" onclick="openQuiz(${id})">Quiz Me</button>
  `;
  openModal('conceptModal');
}

the overlay sits below the modal — and the modal starts invisible

Note what the CSS says: a modal starts with opacity: 0 and pointer-events: none. It is in the page, but it cannot be seen and cannot be tapped. Only the .open class turns it on. That class is added by openModal — and that tiny function is the whole system.

The whole modal systemapp.jsopenModal, closeModal, initModals
let modalStack = [];

function openModal(id) {
  const modal = document.getElementById(id);
  if (!modal) return;
  const overlay = document.getElementById('modalOverlay');
  if (modalStack.length === 0) overlay.classList.add('open');
  modal.classList.add('open');
  modalStack.push(id);
}

function closeModal() {
  if (modalStack.length === 0) return;
  const id = modalStack.pop();
  const modal = document.getElementById(id);
  modal.classList.remove('open');
  if (modalStack.length === 0) {
    document.getElementById('modalOverlay').classList.remove('open');
  }
}
an array, one overlay, and a rule: the overlay lives while the stack lives

That is the entrance. The concept card opens because openModal('conceptModal') runs. The overlay opens only when the stack was empty. Now the learner sees the sheet — and the page behind it is still alive. Next, the quiz.

02

The Stack

Two modals at once — by design

The quiz opens on top of the concept. The concept does not close.

The learner taps "Quiz Me". The app does not replace the concept modal. It opens the quiz modal on top of it. Both are in the DOM, both have the .open class, and the quiz wins because its z-index is higher.

The app tracks this with one array: modalStack. Every open pushes an id. Every close pops one. The overlay follows one rule: it appears when the stack goes from empty to one, and disappears when the stack returns to empty.

So the stack can hold several modals at once. A phase-complete modal can appear above the quiz, and the quiz is still open underneath. That is not a bug — it is the design. The sheet on top is the one that accepts taps; the one below waits.

a seventh modal that only exists when a phase ends

Six modals live in the markup: profile, concept, quiz, resources, challenge, reflection. One more appears only when it is needed: the phase-complete modal is built in JavaScript and removed after it closes. The stack does not care how a modal was born.

03

Four Ways Out

Tap the overlaypointerthe dim area calls closeModal() — the top modal only
Press Escapekeyboarda keydown listener on the document calls closeModal()
Swipe the handletouchpull the handle down past 80px — concept modal only
Use the buttonstapDismiss, Done, Continue — every modal has one

Four paths, one function. Every path ends at closeModal(), so every path behaves the same: the top modal closes, the one below it becomes reachable again.

The interesting one is the swipe. It is bound only to the concept modal's handle, and it is a touchstart/touchend pair with a threshold of 80 pixels. A short drag does nothing. A pull past the threshold closes the modal — the same closeModal() as the buttons.

The swipe-down handlerapp.js80px threshold, concept modal only
const conceptHandle = document.querySelector('#conceptModal .modal-handle');
if (conceptHandle) {
  let swipeActive = false;
  let startY = 0;
  conceptHandle.addEventListener('touchstart', (e) => {
    swipeActive = true;
    startY = e.touches[0].clientY;
  }, { passive: true });
  document.addEventListener('touchend', (e) => {
    if (!swipeActive) return;
    swipeActive = false;
    const endY = e.changedTouches[0].clientY;
    if (endY - startY > 80) closeModal();
  }, { passive: true });
}
the swipe is one channel — the threshold is what makes it feel deliberate

Escape works the same way on every page of the app: a single document-level listener. No modal registers its own key handler. The overlay tap is the simplest path of all — the overlay is one element, its click handler is closeModal itself.

The Chain

Quiz Me — the modal that opens a modal

One button opens a second sheet. The first one stays open underneath.

The concept sheet's footer is rendered by openConcept with one button: "Quiz Me". Its handler is openQuiz(id) — which renders the question and options into the quiz modal, then calls openModal('quizModal'). That is the stack in action: the quiz is pushed on top of the concept.

Quiz Meapp.jsopenQuiz renders, then stacks
function openQuiz(id) {
  const concept = CONCEPTS.find(c => c.id === id);
  if (!concept) return;
  quizAnsweredCorrectly = false;

        <button class="quiz-option" data-correct="${opt.correct}" onclick="checkAnswer(this, ${opt.correct}, ${id})">${opt.text}</button>
      `).join('')}

  `;
  openModal('quizModal');
}
same shape as openConcept: render, then open

Next Concept → — the 180ms hand-off

A correct answer closes the quiz and opens the next concept.

A correct answer replaces the quiz footer with two buttons: "Next Concept →" and "Done". The next button does a two-step dance: closeModal(), then 180 milliseconds later openConcept(nextId). The pause lets the closing animation finish before the next sheet slides in.

That hand-off pattern — close, wait, open — appears again in the bookmarks list. It is the app's way of chaining sheets without ever stacking two at once by mistake.

The hand-offapp.jsclose, wait 180ms, open
const nextConcept = CONCEPTS.find(c => c.id > conceptId);
const nextBtn = nextConcept ? `<button class="btn btn-primary" onclick="closeModal();setTimeout(()=>openConcept(${nextConcept.id}),180)">Next Concept →</button>` : '';
document.getElementById('quizFooter').innerHTML = `
  ${nextBtn}
  <button class="btn btn-secondary" onclick="closeModal()">Done</button>
`;

05

Bookmarks & State

The ★ button — state inside the sheet

The modal is not just chrome. It carries the learner's state.

Inside the concept sheet, next to the title, sits a bookmark button. Tapping it toggles the concept in data.bookmarks, saves the whole state object, and re-renders the concept — so the ★ reflects the new state. The same data drives the profile modal's bookmark list.

The reflection modal goes further: closing it saves a draft. closeModal has a special case for reflectionModal — it reads the textarea, the mood, and the prompt, and stores them before the sheet closes. Closing is not losing.

Bookmark toggleapp.jstoggle, save, re-render
function toggleBookmark(id) {
  const data = getData();
  const idx = data.bookmarks.indexOf(id);
  if (idx >= 0) {
    data.bookmarks.splice(idx, 1);
  } else {
    data.bookmarks.push(id);
  }
  saveData(data);
  openConcept(id);
  renderProfile();
}
the modal re-renders from the saved state
Close = saveapp.jscloseModal's reflection special case
function closeModal() {
  if (modalStack.length === 0) return;
  const id = modalStack.pop();
  const modal = document.getElementById(id);

  if (id === 'reflectionModal') {
    const text = document.getElementById('reflectionText').value.trim();
    if (text || currentMood || currentPromptIndex !== null) {
      const data = getData();
      data.draftReflection = { text, mood: currentMood, promptIndex: currentPromptIndex };
      saveData(data);
    }
  }

  modal.classList.remove('open');
  if (modalStack.length === 0) {
    document.getElementById('modalOverlay').classList.remove('open');
  }
}
one function, one extra duty — close is a save point for the reflection
06

Glass & Tokens

The visual layer — glass from two blurs

The sheet looks expensive. It is two blur rules and four tokens.

Two backdrop-filter rules make the glass: 6px on the overlay, 32px on the sheet. The overlay's job is to dim the page; the sheet's job is to blur what sits under it. The surface itself is var(--bg-glass) — a semi-transparent token — with a glass border and a large shadow.

On phones the sheet slides to the bottom of the screen and becomes a true bottom sheet: full width, rounded only at the top, sliding up with a transform. The breakpoint is 640px. One CSS rule changes the shape; the JavaScript does not know the difference.

And that is the whole system: one array, one overlay, six sheets in the markup, one more born on demand, four ways out, one chain. The glass is two blurs. The state lives in one object. The concept modal looks like a platform — it is forty lines of vanilla JavaScript.
