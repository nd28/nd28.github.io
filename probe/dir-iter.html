The Tool

What It Does

A local Bun server walks $HOME recursively (skipping Library, .cache, .npm, .bun, symlinks) and finds every directory matching a configurable name — default node_modules, but .git, target, .venv all work via the i key.

nm.tsBunserver: walker, SSE stream, action dispatch
page.htmlHTMLsingle self-contained UI — inline CSS, keymap, animations
the keymap page.html · keyboard
─── keymap ─────────────────────────────────
   n   /   →   /   ␣   next hit
   s                 du -sh on current
   k                 skip + auto-advance
   d                 delete (d again to confirm)
   Esc              cancel pending · clear shell input
   i                 focus search-name input
   !                 shell mode
   ?                 toggle help overlay
───────────────────────────────────────────
8 keys · single-page UI · no mouse required after first click

Architecture

Two endpoints. One REST for client-initiated actions. One SSE stream for server-pushed state. That's it.

REST · 1 endpoint
POST /action {type, ...args} 8 action types dispatch through one table
returns 204 or JSON most actions are 204; shell returns stdout
SSE · 1 stream
GET /events EventSource server pushes full state on every change
client onmessage DOM patches via textContent — no diffing
Both endpoints — same server, ~80 LOC combined. Forms still work as graceful degradation.

The State Shape

One JSON blob. Sent verbatim on every SSE broadcast. The UI is purely reactive — patch this, repaint that.

state object single source of truth
{
  "h":        { seq, d, n, size, p },         // current hit
  "st":       "OK" | "skipped" | "du 142M",  // status line
  "pending":  { p, size } | null,            // delete arming
  "name":     "node_modules",                // search target
  "t":        42,                            // total found
  "s":        3,                             // skipped (persistent)
  "v":        7,                             // visited (in-memory, per-iteration)
  "reload":   false                          // force page reload
}
Visited is in-memory — resets per iteration. Skipped is persisted in skipped.json across sessions.

The Journey

Brainstorm, then five questions. Iteration model, start location, visited scope, dense vs spacious, cadence. Each answer cut the design space in half. Three approaches were on the table — lazy per-click, eager manifest, cached. Lazy won for "simplest."

MVP at ~80 LOC. Bun.serve + form POST to /next. Plain HTML, no JS. Click → server walks DFS, returns first unvisited node_modules, marks visited in memory. Worked the first time.

Size obsession. "Can we hit 150 LOC?" Aggressive compression: minified class names, removed template cruft, merged walk functions. 115 LOC, 5KB. Each round was an edit pass on what was already there.

SSE swap. Replaced full-HTML round-trip with EventSource + JSON patches. ~10× perceived speedup because no full-page repaint. Added 2s toast on server responses. Server now tracks a Set of connected controllers.

HTML split. Moved HTML out of the .ts file into page.html, loaded via readFileSync. Editable in any normal editor. Server shrank, code became easier to navigate.

Keymap + features. n, s, k, d, Esc. Then i for name change, ! for shell mode, ? for help. Two-phase delete with pulsing red banner.

Polish. Exaggerated animations (slide-bounce-scale on hit, color flash on status, pulse on pending). Dense flex layout. Responsive media query for narrow screens.

Stateless-friendliness. Removed clear-on-disconnect (was killing shell input). Removed auto-reload-on-reconnect. Trust SSE to keep state in sync. Show a banner, not a wipe.

Consolidation. Eight REST routes collapsed into one POST /action with {type, ...} body and a dispatch table. Same wire bytes, cleaner server.

Metadata + publish. Author, license, repo, keywords. Created GitHub repo via gh repo create --push. Live at github.com/nd28/dir-iter.

Three Decisions That Shaped It

lazy vs eager

started with "find next unvisited on each click" — full DFS per click. ~43ms first click, sluggish. Switched to eager manifest at startup: one DFS at boot, then n is O(1) cursor advance. Trade-off: 7s startup. Acceptable for a local tool.

EventSource vs fetch

asked "would SSE improve round-trip?" — answer was no, not materially, since events are client-triggered. Both achieve ~10× perceived speedup. Picked SSE anyway for elegance. Cost: ~1.5KB more HTML.

8 routes → 1 dispatch

consolidated /next, /size, /skip, … into one /action with a dispatch table. Forms still work — each has a hidden <input name="type">.

The Bugs

Walker "found only 7 of 62." An over-aggressive name.startsWith(".") skip was silently killing .config, .opencode, .windsurf, .npm, .vscode. Lost ~55 of the 62 node_modules on the system. Fixed by removing the dotfile blanket skip — relying solely on the explicit SKIP_TOP set.

Garbled chars in help text. Server was sending text/html without charset=utf-8; page had no <meta charset>. Browser fell back to Latin-1, so → became â†’. Added both — defense in depth.

"I press n and nothing happens." The whole script failed to parse because cancel-form.hidden = !d.pending uses a hyphenated identifier — JS sees cancel - form (subtraction), not an ID reference. HTML IDs with hyphens need getElementById. Renamed to cancelform. Lesson: pick identifiers that double as valid JS names.

Hidden attribute flakiness on shell. #shell.hidden = false didn't always reactivate it after a class-based toggle. Switched to #shell.closed { display:none } with 2-Esc-to-close — first Esc clears the input, second closes the shell. Behavior matches user expectation now.

What Got Cut

The user said "MVP and rest is for later." Several features were considered and parked:

streaming shell output

push stdout chunks via SSE as the command runs. Trade-off: more code, complex flow control. Still TODO.

auto-trigger reload

wire POST /action reload to fire automatically on config. Manual for now.

action queueing

commands during disconnect fail and toast. Could queue and replay on reconnect. Skipped for MVP.

output limit increase

10KB stdout, 5KB stderr caps are conservative. Could grow with truncation markers.

depth limit

hardcoded at 20. Configurable flag would be trivial but unused.
