01

The Game

Ten Points A Word

It is a journal that runs in a terminal. You open it, you type, and a number in the header goes up. Every finished word is worth ten points, multiplied by a combo meter that climbs while you keep going and drains when you stop. The session ends with a score, and the score goes into a lifetime total that only ever grows. Text lives in a SQLite file at ~/.journal/journal.db.

The combo is the whole idea. A word typed in a steady run is worth up to five times a word typed after a long stare at the ceiling. That is a strange thing to do to a journal, and it is the point: the app is trying to buy you a few more minutes of writing before you stop.

The Constants

The rules of the game are eight numbers in one file. They are worth reading before the rest of the article, because everything that follows is a consequence of them.

the whole rulebook internal/scoring/combo.go
const (
	ComboFloor = 1.0
	ComboCap   = 5.0

	ComboBumpPerWords = 3
	ComboBumpAmount   = 0.1
	ComboBumpMaxGap   = 1500 * time.Millisecond

	ComboDecayStartGap      = 2 * time.Second
	ComboDecayRatePerSecond = 0.08

	ComboHardResetGap = 15 * time.Second

	BasePointsPerWord = 10
)
Three words in a row, each within 1.5 seconds of the last, buy 0.1 on the multiplier. Stop for two seconds and it starts draining at 0.08 a second. Stop for fifteen and it is back to 1.0 whatever it was before.

The multiplier is not a score of the session. It is a reading of the last few seconds. Getting to 5.0 takes about two minutes of unbroken typing, and losing it takes fifteen seconds of not typing. A streak bonus sits on top at the end — 5% per consecutive day, capped at 50% — and that one is about the long run.

The Reading

The Spike

A game that rewards pace needs to know your pace, and the header wants to show it live. The obvious way to measure it is wrong in a way that only shows up in the first few seconds.

why the denominator has a floor internal/scoring/intensity.go
	// PaceMinElapsed floors the denominator in WPM so the first couple of
	// words in a session (or right after a long pause) don't produce a
	// spurious spike — e.g. 2 words 1 real second apart would otherwise
	// imply 120 WPM.
	PaceMinElapsed = 5 * time.Second
Two words, one second apart, is a true measurement and a useless one. Without the floor the header opens every session by telling you that you write at 120 words a minute.

Pace is counted over a sliding sixty second window, kept separately from the combo. The combo is game feel; this is meant to be a fact.

Median, Not Average

The app also keeps a personal baseline, so it can say whether today is faster than usual. The number it compares against cannot be total words divided by session length, and the reason is written into the type that fixes it.

the baseline problem internal/scoring/intensity.go
// PaceSampler collects live WPM readings taken while the writer is actively
// typing. Its median is the session's representative pace, and unlike a
// wall-clock average (total words ÷ session duration) it isn't dragged
// toward zero by thinking time — which matters because the same readings
// are what the intensity ratio divides by. Comparing a burst-measured live
// reading against a pause-diluted baseline inflates every ratio.
A journal session is mostly pauses. Divide by the wall clock and the baseline sinks, and then every live reading looks like a personal best.

An empty string doing real work. The retrospective tag and the live header use two different functions on purpose. IntensityTier returns nothing at ordinary pace, so old sessions written before a baseline existed stay unlabelled instead of carrying a word they never earned. LiveTier always returns a word — Warming, Cruising, Focused, Intense, Frantic — because a header that goes blank is a header you stop trusting.
