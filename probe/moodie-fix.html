01

What Broke

The Symptom

moodie loads and draws its whole UI — orbs, nav, theme, settings — but none of it responds. Tap any orb, any nav item, any setting: nothing happens. No error pop, no toast. The screen is a painting.

index.htmlsingle filemarkup + CSS + all JS inline
sw.jsSWmoodie-v1, cache-first shell

Evidence

Loading it in a controlled browser shows the script never ran — one parse error, and the whole inline script is dead.

console before
[error] Uncaught
SyntaxError: Unexpected token ')'
   (moodie — inline script)
node --check pinpoints it further: Unexpected identifier 'system'

The invisible modal

Even after the script parses, taps can still land nowhere. The check-in modal is position:fixed; inset:0; z-index:101 — and while closed it kept pointer-events:auto. Invisible, full-screen, swallowing every tap the app ever received.

hit-testing before
elementFromPoint(theme-button) → DIV#pageMood
                                    └ inside #checkinModal (closed, invisible)
elementFromPoint proved it: the top layer at the button was a child of the closed modal
02

Root Cause

One misplaced quote

The theme buttons in settings are built by appending HTML strings. That string was wrapped in single quotes — and the onclick inside it used single quotes too. The quote before system closed the JS string early.

the broken line renderSettings()
html+='<button ... onclick="setTheme('system')">System</button>';
                  ▲                    ▲
            string closes here    'system' is now an identifier
the parser reads setTheme( then an identifier where it expects a value — SyntaxError

Because it's one inline script, a parse error discards every function in the file. Every onclick attribute pointed at a function that was never defined, so taps had nothing to call. The same slip was repeated on the sibling Light and Dark buttons.

03

The Fix

Theme buttons (3 lines)
beforesingle-quoted string wrapping setTheme('system')
afterdouble-quoted string, interior escaped — setTheme('system') intact
Service worker
beforemoodie-v1 cache-first — the old broken shell kept serving
afterbumped to moodie-v3, network-first — every load fetches the freshest shell
Closed modals
before.modal closed: inset:0; z-index:101; pointer-events:auto — an invisible full-screen tap trap
afterpointer-events:none + visibility:hidden while closed; auto only when .open

Verification

node --check is clean. Live in a controlled browser: console shows no script error, and hit-testing (elementFromPoint) proves no invisible layer sits above any button — the real flow works: open a check-in, pick a mood, the bloom plays, the emotion page advances, plant completes.
